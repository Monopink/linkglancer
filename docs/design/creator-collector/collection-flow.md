# Collection Flow Notes

- `creator_collector` 提供很轻的启动面板和独立的采集进度窗口。
- 不引入国家任务概念；用户先在页面内自行切换国家和筛选条件，再开始采集。
- 单次采集任务只对应一次采集会话与一次正式任务创建。
- 开始采集前先弹出浏览器确认，确认人工已完成登录、筛选、验证码等准备动作。
- 采集的主策略是驱动真实页面滚动，并捕获页面真实发出的列表请求响应。
- 不依赖程序脱离页面主动构造后续分页请求；页面保持打开，采集以真实页面请求为准。
- 采集运行时要尽量减轻页面负担：
  - 默认屏蔽非必要静态资源，例如图片、媒体和字体。
  - 只保留必要的页面脚本、文档和列表接口请求。
  - 滚动推进以“单次动作 + 等待真实响应”为主，不做激进的多重滚动触发。
- 滚动容器应在首次识别后缓存；仅在容器失效时重新探测，避免每次推进都全页扫描 DOM。
- 结束条件以分页 `has_more == false` 为主，同时要有重复页、空页和安全上限保护。
- 采集结果按页增量写入应用 SQLite 中的临时采集会话，不以整包 JSON 定时重写为主链路。
- 临时采集会话至少要保存：
  - 浏览器配置
  - 页面 URL
  - 当前状态
  - 已采集条数
  - 已抓取页数
  - 最后提示
  - 增量写入的达人原始行数据
- 用户点击“保存并创建任务”后，程序从临时采集会话导出 `xlsx`，再走现有任务创建流程生成正式任务。
- 正式任务创建成功后，对应临时采集会话标记为已完成并清理数据。
- 如果程序异常退出或采集被中断，下次打开“新建采集任务”窗口时，需要检查是否存在未完成且有数据的临时采集会话，并提示用户：
  - 保存并创建任务
  - 放弃未保存数据
