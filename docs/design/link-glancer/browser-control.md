# Browser Control Notes

- 浏览器内容始终在受控外部窗口中展示，主窗口只负责流程控制。
- 浏览器控制层保持可替换；业务层不直接依赖 Playwright 细节。
- 每个浏览器配置复用自己的私有用户目录，这个目录由应用管理。
- 开始人工检查前必须先打开确认页；确认页关闭后才建立正式检查页面和缓冲页面。
- 确认页 URL 优先取任务快照里的 `confirm_url`，为空时退回第一条任务 URL。

## 运行时页面模型

- 运行时只存在一个“当前检查页”。
- 运行时可以存在多个“缓冲页”，但缓冲页不参与历史回看语义。
- 程序在内存中维护 `task_index -> page` 的受控映射，并区分：
  - `current_review_page`
  - `prefetch_pages`
  - `blocked_page`
- 数据库不记录浏览器物理标签序号，只记录任务进度、草稿和正式结果。

## 打开与补页规则

- 任务快照中的打开页数表示最大页面窗口上限 `max_open_pages`。
- 系统每轮最多新增 2 个缓冲页。
- 启动检查时，先打开：
  - 1 个当前检查页
  - 最多 2 个缓冲页
- 后续每次正式提交成功后：
  - 关闭刚完成的当前检查页
  - 提升一个已就绪缓冲页为新的当前检查页
  - 再按窗口上限补页，但单轮新增不超过 2 个
- 总打开页数始终不超过 `max_open_pages`。

## 缓冲异常规则

- 缓冲页出现验证码、错误页或未就绪时，必须立即处理。
- 缓冲异常处理流程：
  - 将异常缓冲页切到前台
  - 尝试刷新并重新探测
  - 若恢复正常，则跳回当前检查页
  - 若仍异常，则弹出确认提示，等待用户在浏览器中手动处理
  - 用户确认后重新探测，并在处理结束后跳回当前检查页
- 当前检查页与历史回看导航不共享浏览器状态；历史回看不会驱动浏览器切页。

## 关闭与恢复规则

- 只有当前检查页在正式提交成功后才会被关闭。
- 保存草稿、历史回看、修改已提交结果都不会关闭或重排浏览器页面。
- 任务已完成时，不再启动浏览器；已完成数据只能通过任务界面回看和编辑。
